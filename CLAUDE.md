# Infall: Escape The Collapse

## Hard rule for code

- **Hard Rule (2026-10-23):** Once we begin coding, FTL must not be mentioned anywhere in the code. No code, and no
  direct copies of anything, may be taken from FTL. This is an inspired work and will not plagiarize FTL directly.

A design-stage project: we are writing a game design document, not building the game yet.

- Follow `docs/game-project-standards.md`: standard rules (workflow, labelling of plans/steps/questions,
  branch rules), elegant code principles, and the designer's game design philosophy.
- `docs/gdd.html` is the game design document. Points are lettered per section (e.g. 2A). Points in the design
  docs are tagged as in `docs/tag-styles.md`; follow it when adding or editing points. Undiscussed ideas go in `docs/ideas.md`.
- Concerns to save for later, if heromedel agrees, go in `docs/concerns.md`.
- A shared, co-editable copy of the GDD exists at https://claude.ai/artifact/DNRJEFZkzS4zBL1nPHoLmX. Don't keep
  it in sync automatically; when the user asks to see the GDD, ask whether they want the git version or the
  editable one, and update the editable one only then.
- The user's original idea document is a Google Doc (snapshot in `docs/original-design-idea.md`); others,
  e.g. Nina, may add ideas there.

## About the designer

- Mechanics should feel like FTL (treated as a genre) unless a decision says otherwise (GDD 1C).
- Loves optional settings. A feature that departs from FTL can be a toggle so players can make the game more
  like FTL. Settings are written with the default first, e.g. `Multi Target Lasers: On > Off`.
- Number discussion points (1, 2, 3…) so they can be answered by number.
- Work one major, high-level question at a time: the one that must be answered before deeper questions can be.
  If you could list more than ~6 separate questions, you are not at that level. Don't go into tactics or details
  that depend on things not yet defined.
- When describing races or other designed content, state only what the docs say. Clearly label anything
  extrapolated as a suggestion; never present it as part of the design.
- Call the "." a period, never a full stop.
- "Minimal" means unnoticeable, default or trivial. E.g. a ship's minimal power is not enough to power a
  system.

## The Creative 3-6 Rule

When doing creative work, make 3-6 ideas and pick the best one. See if it matches the rest of the game design and
content, allowing the normal amount of creative variation. Then create it in 3-6 ways and pick the best, then look at
it and improve it 3-6 times. These are minimums. When done, compare it again to the goal, lore, game systems and
design, allowing a normal amount of alteration and creativity: does it fit? If not, try again 3-6 times. Then give
the final best result or results.
