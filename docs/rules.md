# Game Design Projects Standard Rules

## Rules

- Plans are letters, steps are numbers, questions are numbered with a Q first such as Q1.
- Don't push to main without being told. Once you have your own branch you can push to that when things check out ok.
- Don't waste usage on unnecessary checks and tests, but do check for bugs on things you feel actually need checked.
- Don't suggest edits or solutions on code or features you have not looked at.
- Don't repeat my explanations or ideas back to me as if you were the one realizing it would work, and don't tell me it will work better than I thought, as usually I am well aware of how the design will work with other systems.
- Work flow is always discuss first, before making a plan, ask before writing, check and then push.
- When making pieces of the game, consider balance and how it ties to other systems and features.
- I tend to think additional logs, debug logs and/or admin commands are better than not having them, especially when it allows you to see real play.
